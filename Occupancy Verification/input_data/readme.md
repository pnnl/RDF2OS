# Input Data Folder

This folder holds the data required for the Occupancy Verification workflow. The workflow expects two categories of inputs:

1. The simulation output files produced by the occupancy simulator
2. The Excel configuration workbook that defines the target occupancy values

---

## Folder structure

```text
input_data/
├── OOS_config_files/
│   └── input_{CONFIG_NAME}.xlsx
└── simulation_results/
    └── {CONFIG_NAME}/
        ├── occSim.csv
        ├── occSim_by_Occupant.csv
        └── output_xml.xml
```

---

## OOS_config_files

This folder contains the Excel workbook used as the configured target input for each scenario.

This workbook is typically generated by the occupancy simulation GUI, not created manually. The GUI saves a run-specific workbook in the simulation summary folder, for example:

[../Occupancy Simulation GUI/simulation_results/2026-09-14_16_00/simulation_summaries/2026-09-14_16_00_temp_input.xlsx](../Occupancy%20Simulation%20GUI/simulation_results/2026-09-14_16_00/simulation_summaries/2026-09-14_16_00_temp_input.xlsx)

That file should then be copied or renamed into this folder using the verification naming convention.

Naming rule:
- File name must be `input_{CONFIG_NAME}.xlsx`
- Example: `input_hflm_TYPI.xlsx`
- The config name in the file name must exactly match the config name used in `config.py`

Required workbook structure:
- `space_input`
- `space_type_input`
- `behavior_input`

### space_input
This sheet maps each room or enclosure to a space type and other room attributes.

Expected columns:
- `Room/Enclosure`
- `Number of occupants`
- `Occupant density (m^2/person)`
- `Area (m^2)`
- `Qty`
- `Space Type`

### space_type_input
This sheet defines the occupancy assumptions for each space type. It is arranged in paired columns, with the space-type name followed by its default value column.

The script reads this sheet to classify spaces and compare configured occupant-type percentages.

### behavior_input
This sheet defines behavioral targets such as time spent in office, meeting room, auxiliary, and outdoor space categories, plus additional behavior-related metrics.

The script filters the rows that represent percentage-based behavior values and ignores non-percent rows such as average stay-duration entries.

## simulation_results

This folder contains the raw results from the occupancy simulation.

For each configuration, create a folder named exactly `{CONFIG_NAME}` and place the following files inside it:

- `occSim.csv`
- `occSim_by_Occupant.csv`
- `output_xml.xml`

The files must all belong to the same simulation run and the same configuration label.

### File descriptions

- `occSim.csv`: room-level occupancy output by timestep
- `occSim_by_Occupant.csv`: occupant-level occupancy output by timestep
- `output_xml.xml`: XML metadata used to map occupant IDs and office assignments

---

## Required naming consistency

The following three items must match exactly:

1. The folder name under `simulation_results`
2. The Excel file name under `OOS_config_files`
3. The `CONFIG_NAMES` entry in `config.py`

Example:

```python
CONFIG_NAMES = ['hflm_TYPI']
```

This corresponds to:

```text
input_data/
├── OOS_config_files/
│   └── input_hflm_TYPI.xlsx
└── simulation_results/
    └── hflm_TYPI/
        ├── occSim.csv
        ├── occSim_by_Occupant.csv
        └── output_xml.xml
```

---

## Final note

The workflow is strict about file names and workbook structure. A mismatch in names, missing sheets, or a different file layout can cause the script to fail or skip parts of the analysis. Using the exact format above ensures the verification workflow can load and compare the configured and simulated occupancy data correctly.

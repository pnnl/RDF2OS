# Occupancy Verification Workflow

This workflow compares the occupancy targets you define in Excel against the raw results generated by the occupancy simulator. It checks whether the modeled behavior matches the intended configuration and produces plots and summary files for review.

It produces the following outputs:
- Percent-difference heatmaps
- Pass/fail heatmaps
- Excel reports with configured values, simulated values, and the difference between them
- Optional deeper analysis files for behavior underuse and meeting-length bias

---

## Required inputs

The verification workflow expects a specific folder structure and exact file names. The names are case-sensitive.

### 1) Simulation output files

Place all simulation results for each configuration in:

`input_data/simulation_results/{CONFIG_NAME}/`

where `{CONFIG_NAME}` is the configuration name you want to verify. For example:

`input_data/simulation_results/hflm_TYPI/`

Inside each configuration folder, the workflow expects exactly these files:

- `occSim.csv` — room-by-room occupancy counts over time
- `occSim_by_Occupant.csv` — occupant-level time series for each person
- `output_xml.xml` — XML metadata generated by the occupancy simulator

These files must come from the same simulation run and use the same configuration label.

### 2) Configuration Excel file

Place the Excel file for each configuration in:

`input_data/OOS_config_files/input_{CONFIG_NAME}.xlsx`

For example:

`input_data/OOS_config_files/input_hflm_TYPI.xlsx`

This workbook is typically generated by the GUI in the simulation workflow, not created manually. The GUI writes a temporary Excel workbook into the run-specific summary folder under [Occupancy Simulation GUI](../Occupancy%20Simulation%20GUI), for example:

[Occupancy Simulation GUI/simulation_results/2026-09-14_16_00/simulation_summaries/2026-09-14_16_00_temp_input.xlsx](../Occupancy%20Simulation%20GUI/simulation_results/2026-09-14_16_00/simulation_summaries/2026-09-14_16_00_temp_input.xlsx)

After it is generated, copy or rename it to the verification input format so it matches the naming convention above.

Important rules:
- Keep the `input_` prefix exactly.
- Use the same configuration name in the file name as the folder name under simulation_results.
- The configuration workbook must contain these sheets:
  - `space_input`
  - `space_type_input`
  - `behavior_input`

## Required Excel sheet formats

### space_input sheet
This sheet defines each room or enclosure and its assigned space type.

Expected columns:
- `Room/Enclosure`
- `Number of occupants`
- `Occupant density (m^2/person)`
- `Area (m^2)`
- `Qty`
- `Space Type`

This sheet is used to map room names to space types and to identify the occupancy assumptions associated with each room.

### space_type_input sheet
This sheet defines the occupancy parameters for each space type, organized as paired columns. The first row usually contains the space-type names, and the next row(s) contain the parameter labels and values.

The workflow reads these values to determine:
- office percentages by occupant type
- working assumptions for each space type
- which spaces are office, gathering, or other categories

Example structure:
- Column A: space type name
- Column B: default value
- Column C: next space type name
- Column D: default value
- and so on

The actual parameter wording and categories are not arbitrary; the code looks for typical occupancy metrics like occupant percentage, occupancy density, and meeting-related inputs.

### behavior_input sheet
This sheet defines behavior-related configuration values such as:
- how much time people spend in each category (own office, other office, meeting room, auxiliary, outdoor)
- average stay duration
- typical arrival/departure patterns or related behavioral parameters

The workflow specifically reads the rows that represent percent-based behavior metrics and excludes non-percent rows such as stay-duration entries.

## Configuration naming convention

Open `config.py` and edit the `CONFIG_NAMES` list to match the exact config names you want to run.

Example:

```python
CONFIG_NAMES = ['hflm_TYPI']
```

This must match:
- the folder name under `input_data/simulation_results/{CONFIG_NAME}/`
- the Excel file name `input_{CONFIG_NAME}.xlsx`
- the config label used in the simulation results

If there is any mismatch, the workflow will fail or produce incomplete results.

---

## How to run

From inside the Occupancy Verification folder, execute:

```bash
python config.py
```

Status messages will print in the terminal, and output files will be saved to:

`verification_results/{CONFIG_NAME}/`

---

## Output folder structure

Each config produces a results folder similar to:

`verification_results/hflm_TYPI/`

Typical outputs include:
- percent_difference/plots
- percent_difference/data
- pass_fail/plots
- pass_fail/data
- analysis/ (underuse and meeting-length bias summaries when generated)

---

## Common troubleshooting

- If the workflow says a file is missing, confirm the folder name and file names exactly match the config.
- If the workbook is missing a required sheet, add the missing sheet or rename it to match the expected names.
- If a sheet has unexpected columns or blank rows, the script may misread the data or return incomplete results.
- The simulation output files should come from the same simulation run; mixing files from different runs or different configs will produce incorrect comparisons.

This workflow is designed to compare a single configuration at a time, or multiple configurations in the same `CONFIG_NAMES` list, as long as each one follows the naming and file conventions above.
